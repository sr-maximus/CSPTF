# Contributing to CSPTF

CSPTF welcomes evidence-backed contributions from security researchers, developers, operators, auditors, legal/compliance specialists and incident responders.

## Contribution types

- New or revised control
- New authorized test case
- Threat or weakness refinement
- Mapping correction
- Case study based on public or sanitized evidence
- Translation
- Tooling, schema or validator improvement
- Editorial and accessibility fixes

## Requirements

1. Open an issue explaining the problem and evidence.
2. Use existing identifiers; never renumber released items.
3. Cite primary sources where possible.
4. Separate normative requirements from implementation examples.
5. Keep procedures lawful, authorized, non-destructive and lab-first.
6. State limitations and chain/platform assumptions.
7. Add or update tests when changing machine-readable catalogs.
8. Do not include private keys, credentials, customer data, exploit payloads against live targets or confidential incident material.

## Pull request quality gate

- Catalog validator passes.
- JSON conforms to schemas.
- Markdown links are valid.
- The change has a clear rationale and source.
- Safety and responsible-disclosure implications are addressed.
- At least one maintainer review is required; high-impact changes require two reviewers.

By submitting a contribution, you agree that it may be distributed under Apache-2.0.
